# Ludeo SDK Integration Skill

An open Agent Skill that walks an AI coding agent through integrating the [Ludeo](https://ludeo.com) SDK into a game built on a **proprietary C++ engine** — from build setup all the way through state restoration, action mapping and runtime verification.

> Using **Unity** or **Unreal**? Those engines have their own skills — `ludeo-unity-integration` and
> `ludeo-unreal-integration` — which install a real engine plugin instead of wiring the C API by hand.

Works with **Claude Code, Cursor, GitHub Copilot, Codex, Windsurf, Cline, Continue, Gemini CLI**, and 45+ other agents that support the open agent-skills spec.

## Install

In your game's repo, run:

```bash
npx skills add ludeo-labs/core-integration-skill
```

The CLI auto-detects which AI coding agents you have installed and asks where to put the skill. To target specific agents non-interactively:

```bash
npx skills add ludeo-labs/core-integration-skill -a claude-code -a cursor -y
```

To install globally (available to every project on your machine):

```bash
npx skills add ludeo-labs/core-integration-skill -g -y
```

The `skills` CLI is documented at <https://github.com/vercel-labs/skills>.

## Run

Open your game repo in your AI agent and ask it:

> Integrate Ludeo into my game using the `ludeo-integration` skill.

The agent reads `SKILL.md`, picks up the eight-phase workflow, and walks you through each phase. It pauses for confirmation between phases.

You can also jump to a specific phase:

> Continue with phase 5 of the `ludeo-integration` skill.

Phase numbers match the Unity and Unreal skills, so "phase 5" means the same stage of work whichever engine you are on.

## What's inside

| Path | Purpose |
| --- | --- |
| `SKILL.md` | Skill orchestrator with YAML frontmatter and the phase-flow narrative |
| `references/` | Phase workflow docs + reference material loaded on demand |
| `learnings/` | Append-only, sanitized lessons from real integrations (C++ and ported from Unity/Unreal); `learnings/INDEX.md` is generated by `scripts/generate-learnings-index.mjs` |
| `tools/` | Runtime helpers the skill invokes |
| `scripts/` | `validate-skill.mjs`, `bump-skill-version.mjs` (used by CI / release pipeline) |
| `.github/` | Validation + release workflows |

Sequential eight-phase workflow under [`references/`](references):

| Phase | File | Purpose |
| --- | --- | --- |
| 1 | `references/1-build-game-with-sdk.md` | Build environment, conditional compilation, baseline + SDK builds |
| 2 | `references/2-map-game-code.md` | Produce `CODE_MAP.json` of the game's architecture |
| 3 | `references/3-lifecycle-orchestrator.md` | Phase 3 entry point — runs tasks 1–6 |
| 3 · task 1 | `references/3a-find-sdk-integration-points.md` | Identify where SDK calls go |
| 3 · task 2 | `references/3b-create-tdd.md` | Produce Technical Design Document (architecture, strategy, risks) |
| 3 · task 3 | `references/3c-plan-sdk-lifecycle.md` | Plan lifecycle wiring |
| 3 · task 4 | `references/3d-implement-sdk-lifecycle.md` | Implement lifecycle wiring |
| 3 · task 5 | `references/3e-compile-and-fix.md` | Compile, fix, verify |
| 3 · task 6 | `references/3f-classify-save-system.md` | Classify the save system (group + per-entity matrix) |
| 4 | `references/4-map-game-objects.md` | Census of trackable objects, load-bearing flags, wave plan |
| 5 | `references/5-tracking-restore-orchestrator.md` | Phase 5 entry point — the wave loop |
| 5 · task 0 | `references/5a-deep-scope-wave.md` | Deep-scope one wave's objects |
| 5 · task 1 | `references/5b-implement-object-tracking.md` | Wire object registration & capture (per wave) |
| 5 · task 2 | `references/5c-plan-state-restoration.md` | Plan the two-pass restoration flow |
| 5 · task 3 | `references/5d-implement-restoration-flow.md` | Implement the player-flow half — validate, build the moment before Play, resume (once) |
| 5 · task 4 | `references/5e-implement-state-reconstruction.md` | Fill the two-pass `DataReader` read-back |
| 6 | `references/6-actions-orchestrator.md` | Phase 6 entry point |
| 6 · task 1 | `references/6a-map-game-actions.md` | Find action points in game code |
| 6 · task 2 | `references/6b-implement-game-actions.md` | Insert action calls |
| 7 | `references/7-upload-build.md` | Verify the Release build, upload it, and assign it to an environment |
| 8 | `references/8-polish.md` | Gap check, opt-in expansion as new waves, polish, re-upload, completion |

Reference material lives alongside the workflow files:

- `references/ludeo-integration-docs/` — primary integration guides (build, lifecycle, tracking, API reference, research templates, genre playbooks).
- `references/ludeo-studio-mcp.md` — how the agent uses the Ludeo Studio MCP to configure Studio Lab.
- `references/state-file-schema.md` — the integration's state file (`ludeo-integration-plan/integration.json` in your repo): it lets the agent resume an integration across sessions.
- `references/know-your-game.md` — the kickoff questions the agent asks your team in phase 1.
- `config/mcp_config.template.json` — the optional MCP servers (`sdk-docs`, `ludeo-mcp`).

### Optional: MCP servers

With the **Ludeo Studio MCP** (`ludeo-mcp`, OAuth sign-in with your Studio Lab account) connected, the agent
reads your game's environments and configures Studio Lab itself — the beta version name that routes local
runs, goals and constraints, and Global Triggers (never on Production) — instead of asking you to click
through it. `sdk-docs` lets it search the SDK documentation. Both are optional; phase 1 offers to wire them up
from `config/mcp_config.template.json`, and every step falls back to asking you when they are absent.

## Versioning

Stable versions are tagged on GitHub (`v0.1.0`, `v0.2.0`, …). Pin a specific version to keep your team on a known-good release:

```bash
npx skills add ludeo-labs/core-integration-skill#v0.1.0
```

## Updating

```bash
npx skills update ludeo-integration
```

## Uninstalling

```bash
npx skills remove ludeo-integration
```

## Contributing

PRs welcome. CI runs on every PR:

- `node scripts/validate-skill.mjs` — checks `SKILL.md` frontmatter and that every relative path referenced in workflow files resolves on disk.
- `npx skills add ./ --list` — verifies the skill is discoverable.
- A smoke install into a temp directory verifies end-to-end install works.

To release a new version, push a tag matching `v*` (e.g. `git tag v0.2.0 && git push origin v0.2.0`). The release workflow auto-generates notes and publishes the GitHub Release.
